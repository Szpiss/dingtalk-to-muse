# muse-integration：助手侧（以 Muse 为例）

Mac 端只负责把通知变成 JSONL；"读懂"和"提醒"是助手侧的工作。以下是我（Muse）的实际配置，换成其他 AI 助手照着改。

## 架构

```
~/dingtalk-forward/            助手每 15 分钟拉取一次
├── notifications.jsonl   →   按 rowid 去重，只处理新行
├── state.json            →   游标：last_rowid / 连续失败计数 / 上次成功时间
├── inbox-YYYY-MM-DD.md   →   每日分类收件箱
└── pending.md            →   未完成且有明确截止时间的事项（晨间简报消费）
```

拉取方式：Muse 的 `device.invoke` 调配对 Mac 的 `files.read` 命令读文件。
每次重新打开读取，不持有旧文件句柄（Mac 侧是原子替换）。

## 分类规则

| 分类 | 触发 | 动作 |
|---|---|---|
| 作业 | 提到作业/练习/实验报告/提交/上交/课程任务 | 记 inbox；有截止时间→进 pending |
| 截止时间 | 含明确日期/时间（"周五前""10月25日截止""明天交"） | 记 inbox + 进 pending |
| 通知 | 会议/讲座/填表/缴费/学院通知等 | 只记 inbox |
| 测试 | title 为人名、body 为单个数字等 | 只记，不提醒 |

**铁律：不要编造截止时间。**消息里没写明确时间的，一律不建提醒。

## 提醒策略

- 截止时间 **≤48 小时**：建一次性定时提醒（截止前一天 21:00；若截止就是明天，则当天 21:00），内容含事项 + 截止时间
- 截止时间 **>48 小时**：只记 pending.md，晨间简报会带
- 无截止时间的通知：只记账，不打扰

## 静默原则

- 默认轮询成功、无新事项时：**不打扰用户**，只写文件
- 打扰用户的只有两种情况：
  1. 连续 3 次读取失败（且在白天 9:00–23:30）→ 告警：Mac 可能离线或采集脚本异常
  2. 新建了一次性截止提醒 → 附带说一句"已建提醒：XXX（截止YYY）"
- 深夜读取失败不告警（Mac 睡眠属正常）

## 失败处理

- 拉取失败 → `consec_failures` +1，本轮不推进游标
- 成功后清零；若之前发过告警，恢复时附带一句"已恢复"
- 查故障顺序：Mac 侧 `forward.log` → 本侧 `state.json`

## 复制到你自己的助手

任何能做到以下三点的 AI 助手都能复用这套：

1. 定时任务（cron / scheduled job）
2. 读 Mac 上一个本地文件的能力（SSH、`device.invoke`、iCloud 同步盘……）
3. 在某个时间点给你发消息的能力

分类和提醒策略是 prompt 级的东西，照着上面的表写就行。
